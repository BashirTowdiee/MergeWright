# Code of Conduct

## Our standards

MergeWright aims to be a practical, respectful engineering project. Contributors are expected to communicate clearly, assume good intent, and keep discussions focused on the work.

Examples of encouraged behaviour:

- giving constructive technical feedback
- explaining trade-offs and risks clearly
- respecting different experience levels and backgrounds
- keeping review comments specific and actionable
- accepting responsibility for mistakes and correcting them
- prioritising project safety, evidence, and maintainability

Examples of unacceptable behaviour:

- harassment, threats, or personal attacks
- discriminatory language or conduct
- repeated disruption of project discussions
- publishing private information without permission
- dismissive or hostile review behaviour
- knowingly bypassing project safety expectations

## Scope

This code of conduct applies to project spaces including issues, pull requests, discussions, documentation, and other collaboration channels associated with MergeWright.

## Enforcement

Project maintainers may take action to protect the project and its contributors. Actions may include clarification, moderation, removal of comments, closing conversations, or restricting participation.

Enforcement should be proportional, documented where appropriate, and focused on maintaining a safe and productive engineering environment.

## Reporting

If you need to report unacceptable behaviour, contact the repository owner directly. Do not include private information or security-sensitive details in a public issue.

## Project-specific expectations

MergeWright deals with AI-assisted code delivery, write-safety, and repository automation. Contributors should be especially careful when proposing changes that affect execution, file writes, git operations, evidence handling, or review gates.

Respectful disagreement is welcome. Unsafe shortcuts, hidden automation, or bypassing review safeguards are not.
